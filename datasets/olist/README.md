# Olist OLTP source database (shared by L04, L08, L12, capstone)

The labs use the **Brazilian E-Commerce Public Dataset by Olist**
(<https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce>) as the
"production" OLTP database that we ingest from (Sqoop / Spark JDBC / Debezium CDC)
and model (dbt).

Because Kaggle requires a login, the repo ships a **synthetic seed with the
same schema and column names** so every lab works offline and out of the box.

| File | Purpose |
|---|---|
| `init/01_schema.sql` | Tables, primary keys, FKs (ON DELETE CASCADE), `orders.order_seq` surrogate key, `updated_at` indexes and an `updated_at` trigger |
| `init/02_seed.sql` | Synthetic data (generated — do not edit): 5,000 orders, 5,000 customers, 312 sellers, 1,500 products, 5,852 order items, 5,472 payments (~3.4 MB) |
| `generate_seed.py` | Stdlib-only generator for `02_seed.sql` (deterministic, `--seed 42`) |
| `load_kaggle_csv.sql`, `load_kaggle.sh` | Replace the synthetic rows with the real Kaggle CSVs (~99k orders) |

## Using it in a lab's docker-compose

```yaml
services:
  postgres:
    image: postgres:18.6
    environment:
      POSTGRES_USER: olist
      POSTGRES_PASSWORD: olist
      POSTGRES_DB: olist
    volumes:
      - ../datasets/olist/init:/docker-entrypoint-initdb.d:ro
```

The official image runs `*.sql` files in `/docker-entrypoint-initdb.d` **only
when the data volume is empty** (first start). To re-seed: `docker compose down -v`
and start again.

## Tables

Column names are identical to the Kaggle CSVs, including the original typos
`product_name_lenght` and `product_description_lenght`.

| Table | Primary key | Kaggle file |
|---|---|---|
| `customers` | `customer_id` | olist_customers_dataset.csv |
| `sellers` | `seller_id` | olist_sellers_dataset.csv |
| `products` | `product_id` | olist_products_dataset.csv |
| `orders` | `order_id` | olist_orders_dataset.csv |
| `order_items` | (`order_id`, `order_item_id`) | olist_order_items_dataset.csv |
| `order_payments` | (`order_id`, `payment_sequential`) | olist_order_payments_dataset.csv |

Course additions (not in Kaggle):

* **`updated_at timestamp NOT NULL`** on every table. Seed values are historical
  (2016–2018). A `BEFORE UPDATE` trigger (`set_updated_at()`) bumps it to `now()`
  whenever a row changes, unless the UPDATE sets `updated_at` explicitly — this is
  what makes Sqoop `--incremental lastmodified`, Spark watermark reads and CDC demos work.
* **`orders.order_seq bigint`** — numeric surrogate key (`GENERATED BY DEFAULT AS IDENTITY`,
  `UNIQUE`), assigned in purchase-time order (1 … 5000 in the seed; new rows get the next value).
  `order_id` stays the primary key. The Olist IDs are 32-char hex *text* hashes, which are poor
  split columns; `order_seq` gives Sqoop `--split-by` / `--incremental append` and Spark JDBC
  `partitionColumn` an evenly distributed numeric range (L04). Date/timestamp columns
  (`order_purchase_timestamp`, `updated_at`) are also valid range-split columns.

Handy "simulate the business" statements for incremental/CDC labs:

```sql
-- a new order arrives (new customer)
INSERT INTO customers (customer_id, customer_unique_id, customer_zip_code_prefix, customer_city, customer_state)
VALUES (md5('new-cust-1'), md5('new-uniq-1'), 1310, 'sao paulo', 'SP');
INSERT INTO orders (order_id, customer_id, order_status, order_purchase_timestamp)
VALUES (md5('new-order-1'), md5('new-cust-1'), 'created', now());
-- an existing order changes status (updated_at is bumped by the trigger)
UPDATE orders SET order_status = 'canceled'
WHERE order_id = (SELECT order_id FROM orders WHERE order_status = 'shipped' LIMIT 1);
```

## Regenerating the synthetic seed

```bash
python3 labs/datasets/olist/generate_seed.py                 # 5,000 orders (default)
python3 labs/datasets/olist/generate_seed.py --orders 20000  # bigger (~14 MB)
```

## Loading the real Kaggle data instead

1. Download and unzip the dataset from Kaggle (free account) — e.g. into
   `~/Downloads/brazilian-ecommerce/`.
2. Start the lab stack that contains Postgres (e.g. `L04_ingestion`) so the schema exists.
3. Run (container name from `docker compose ps`):

   ```bash
   labs/datasets/olist/load_kaggle.sh l04_ingestion-postgres-1 ~/Downloads/brazilian-ecommerce
   ```

   It `TRUNCATE`s the six tables, `\copy`s the CSVs, derives historical
   `updated_at` values and prints row counts (99,441 orders, 112,650 items,
   103,886 payments, 99,441 customers, 3,095 sellers, 32,951 products).

The real data is ~30x larger; everything in the labs still fits in 8 GB RAM, but
Sqoop/Spark imports take longer.
